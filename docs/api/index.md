# API

The backend exposes one GraphQL endpoint and one REST endpoint on port 4000.

| Endpoint                                   | Purpose                                        |
| ------------------------------------------ | ---------------------------------------------- |
| `POST /graphql`                            | GraphQL API used by the desktop app and workers |
| `GET /experiments/:experimentId/report`    | PDF report for an experiment                   |

## GraphQL

- The schema is generated by `type-graphql` into `backend/schema.gql` and synchronized to `desktop/schema.graphql`.
- Resolvers live in `backend/src/modules/*/graphql` (`auth`, `computations`, `experiments`, `files`, `storage`, `technologies`) and `backend/src/graphql` (`health`, server info).
- Client-side conventions: [GraphQL in the desktop app](graphql-client.md).
- Domain behavior of the run-related operations: [Experiments and computations](../domain/experiments.md#graphql-behavior).

Quick check that the backend is running:

```bash
curl -sS http://localhost:4000/graphql \
  -H 'Content-Type: application/json' \
  --data '{"query":"{ health }"}'
```

## REST report

`GET /experiments/:experimentId/report` returns a PDF (`Content-Disposition: attachment`) that is
generated with `puppeteer` (Chromium). It contains the experiment name, description and creation
date, the graph and its settings, the source file details, the pipelines with their computing
results and machine information, and the optimization result and history.

Responses: `400` for a missing or invalid experiment `_id`, `404` when the experiment does not
exist, `500` when the PDF cannot be generated, otherwise `200` with the PDF. The desktop app shows
the download button only for `completed` experiments. The endpoint currently performs no
authentication.

A complete API reference (operations, examples, error messages and the authentication model) is planned and
is not part of this page yet.
