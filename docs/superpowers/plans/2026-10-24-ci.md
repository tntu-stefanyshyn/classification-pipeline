# Continuous integration implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task.

**Goal:** Test all three workspaces and build a Windows x64 installer on every pull request and push to main, without deploying or publishing releases.

**Architecture:** One GitHub Actions workflow runs independent Node.js tests, Python tests, Docker builds, and a native Windows installer build. A final `CI passed` job reports whether every check succeeded. Windows installers are retained as workflow artifacts.

**Tech Stack:** GitHub Actions, Node.js 22, npm workspaces, Python 3.11, pytest, Docker, Electron Forge.

**Spec:** User decisions in this conversation: CI for desktop/backend/aws-jobs; Windows x64 only; no deployment; preserve maint changes in main before deleting maint.

## Global constraints

- Run on every pull request, every push to main, and manual dispatch.
- Do not publish releases, push container images, or deploy services.
- Keep existing application authentication behavior.
- Transfer all maint commits to main before deleting the remote branch.
- Use the committed npm lockfile and generate GraphQL code from the local schema.

## Review focus

- Windows installation must not depend on Unix find/rm commands.
- Generated-code cleanup must preserve handwritten files and not follow symlinks.
- Authentication tests must require a token even in development.
- Failed or cancelled checks must make the aggregate check fail.
- Windows artifacts must actually exist; no successful upload of an empty directory.
