# Експерименти та обчислення

На цій сторінці зібрано правила для експериментів, графів і запусків. Вона охоплює як правила бекенду, так і
те, як їх застосовують конструктор у десктопному застосунку та сторінка деталей експерименту.
Українські відповідники термінів наведено в [глосарії](../index.uk.md#глосарій).

## Терміни

- **Експеримент (experiment)**: набір даних (завантажений CSV-файл) разом із графом етапів.
- **Граф (graph)**: вузли (технології), з'єднані ребрами; кожен вузол належить до певного **етапу**.
- **Етап (stage)**: один із `PREPROCESSING`, `DATA_ENHANCEMENT`, `FEATURE_EXTRACTION`, `DIMENSIONALITY_REDUCTION`, `CLASSIFICATION` у цьому порядку.
- **Шлях (path)**: ланцюжок вузлів від кореневого вузла до листка.
- **Конвеєр (pipeline)**, або запуск: обчислення одного шляху в одній черзі. Один конвеєр створюється для кожної комбінації шляху й обраної черги, коли експеримент переходить у статус `computing`. Якщо обрано і `local`, і `cloud`, на кожен шлях припадає два конвеєри.
- **Черга (queue)**: місце виконання конвеєра: `local` (виконавець у десктопному застосунку) або `cloud` (Docker-виконавець бекенду чи AWS Batch).
- **Крок перехресної валідації (fold)**: кількість кроків перехресної валідації, яку задають у налаштуваннях графа.

## Життєвий цикл статусу експерименту

| Статус          | Значення                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `creating`      | Стан за замовчуванням після створення.                                                               |
| `configuring`   | Встановлюється, коли змінюють вузли графа, налаштування графа або режим обчислень.                   |
| `computing`     | Встановлюється під час запуску обчислень. Створюється один конвеєр на шлях і обрану чергу.           |
| `optimization`  | Встановлюється, поки виконується завдання оптимізації, після обчислення конвеєрів.                   |
| `completed`     | Встановлюється, коли оптимізацію завершено.                                                          |

Дозволені переходи: `creating → configuring → computing → optimization → completed` і
`completed → optimization` (оптимізацію можна запустити повторно).
Експеримент не може перейти в `computing` без прикріпленого доступного CSV-файлу.

## Життєвий цикл статусу конвеєра

| Статус      | Значення                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------- |
| `idle`      | Немає активного запуску. Початковий статус і статус, у який запуск повертається після зупинки. |
| `queued`    | Очікує в черзі на виконавця.                                                              |
| `running`   | Взятий виконавцем і обчислюється.                                                         |
| `completed` | Успішно завершений.                                                                       |

Дозволені переходи: `idle → queued`, `queued → running`, `queued → idle` (коли обчислення
призупиняють), `running → completed`, `running → idle` (коли запуск зупиняють).

Статусів `stopped` і `failed` не існує: після зупинки запуску конвеєр повертається в `idle` зі
службовим повідомленням «Зупинено користувачем». Історія конвеєра фіксує кожну зміну статусу.

## Перевірки

- Порядок етапів графа контролюється: дочірній вузол має належати до пізнішого етапу, ніж батьківський.
- Обчислення можна запустити, лише якщо **кожен** шлях графа містить етап класифікації.
- Налаштування графа вимагають, щоб чотири ваги метрик (`accuracy`, `f1`, `rocAuc`, `ntps`) були в межах 0..1 і давали в сумі 1.
- Налаштування графа вимагають хоча б одну дозволену чергу обчислень, а запуск приймається лише для дозволеної черги.
- Режим обчислень графа (`local`, `cloud`, `both`) обмежує, яку чергу можна використати.
- Зміни експерименту та графа заблоковано після початку обчислень (статуси `computing`, `optimization` і `completed`).
- Оптимізацію можна запустити лише зі статусу `computing` або `completed`, і лише одна оптимізація може виконуватися одночасно. Усі конвеєри в кожній обраній черзі мають бути `completed`.

## Поведінка GraphQL

- `enqueueExperimentRuns` перевіряє налаштування графа й покриття етапом класифікації, а потім переводить конвеєри зі статусу `idle` у `queued`.
- `stopExperimentRun(input: { runId })` зупиняє конвеєр зі статусом `running` і повертає його в `idle`; для будь-якого іншого статусу повертає конвеєр без змін. Якщо є хмарне завдання, його спочатку скасовують.
- `PipelineStatus.idle` також показується в інтерфейсі для шляху, у якого немає запусків.

## Конструктор графа (десктоп)

- Порядок етапів фіксований: попередня обробка → покращення даних → видобування ознак → зменшення розмірності → класифікація.
- Під час додавання вузла дозволено лише етапи, що йдуть після етапу батьківського вузла.
- Редагування вузла не дозволяє змінити його етап на попередній, якщо існує батьківський етап.
- Для етапу класифікації немає кнопки додавання дочірнього вузла.

## Налаштування графа (десктоп)

- Метрики `accuracy`, `f1`, `rocAuc` і `ntps` зберігаються в межах 0..1.
- В інтерфейсі ваги вводяться у відсотках (0–100); сума має дорівнювати 100 % (1 у даних).
- Типи обчислень обирають із мультивибору (локально й у хмарі). Без вибору запуск неможливий.

## Запуск обчислень (`ExperimentDetailsPage`)

- **Картка обчислень** показує таблицю шляхів і дій над ними (запуск, зупинка, перезапуск).
- Колір графа відображає статус шляху:
  - `queued`: синій
  - `running`: жовтий
  - `completed`: зелений
  - `idle`: світло-сірий (запусків немає)
- Обчислення заблоковано, якщо хоча б один шлях не має етапу класифікації.
- Кнопка `info` відкриває модальне вікно з деталями останнього запуску шляху.
- Редагування експерименту, налаштувань графа й етапів графа вимкнено після початку обчислень.

## PDF-звіт

- Кнопка **Завантажити PDF** з'являється лише тоді, коли статус експерименту — `completed`.
- REST-ендпоінт: `GET {API_BASE}/experiments/:experimentId/report`, де `API_BASE` — GraphQL URL без `/graphql`. Докладніше: [REST-звіт](../api/index.md#rest-report) (англійською).
